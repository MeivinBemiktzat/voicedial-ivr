המערכת מתמללת את הדיבור בעצמה (לא באמצעות מנוע התמלול המובנה של ימות),
ומחייגת ליעד המבוקש.


## הגדרת Hugging Face Storage (S3)

המערכת שומרת קובץ JSON אחד לכל מספר מחייג (אנשי קשר + היסטוריית שיחות)
ב-Hugging Face Storage, דרך ממשק תואם S3.

> **מקור:** [תיעוד רשמי - Hugging Face Hub, Storage Buckets (S3)](https://huggingface.co/docs/hub/storage-buckets-s3)

### שלב 1: יצירת Bucket

1. היכנסו לחשבון Hugging Face שלכם (או ארגון).
2. צרו Storage Bucket חדש (דרך הדף הרלוונטי בהגדרות החשבון/הארגון).
   רשמו לעצמכם את **שם ה-bucket**.

### שלב 2: הפקת מפתחות S3 (Access Key / Secret Key)

1. עברו ל-[Access Tokens](https://huggingface.co/settings/tokens) בהגדרות החשבון.
2. צרו טוקן חדש. בחרו הרשאת **Write** (כדי לאפשר גם כתיבה, לא רק קריאה) -
   הרשאות המפתח יורשות מהטוקן.
3. בתפריט הנפתח של הטוקן, בחרו **Generate S3 credentials**.
4. יוצג **Access Key ID** (מתחיל ב-`HFAK...`) ו-**Secret Access Key**.
   **העתיקו את שניהם מיד - ה-Secret מוצג פעם אחת בלבד.**
5. מומלץ (לא חובה): אם זה טוקן מסוג fine-grained, הגבילו אותו (scope)
   רק ל-bucket/namespace הרלוונטיים לפרויקט הזה.

### שלב 3: זיהוי ה-namespace שלכם

ה-namespace הוא שם המשתמש או הארגון שלכם ב-Hugging Face (מה שמופיע
בכתובת ה-URL של הפרופיל שלכם, למשל `huggingface.co/your-username`).
יש לרשום אותו - הוא ישמש לבניית כתובת ה-endpoint.

### שלב 4: חיבור ה-boto3 (מוטמע כבר בקוד)

לפי התיעוד הרשמי, ה-endpoint הנכון הוא:

```
https://s3.hf.co/<namespace>
```

וה-boto3 client חייב את ההגדרות הבאות (region קבוע, addressing path-style):

```python
boto3.client(
    's3',
    endpoint_url=f'https://s3.hf.co/{namespace}',
    aws_access_key_id=access_key,       # HFAK...
    aws_secret_access_key=secret_key,
    config=Config(
        region_name='us-east-1',
        s3={'addressing_style': 'path'},
        request_checksum_calculation='when_required',
        response_checksum_validation='when_required',
    ),
)
```

כל זה כבר מוטמע ב-`api/storage.py` - אתם רק צריכים לספק את ארבעת
משתני הסביבה (ר' להלן).

## פריסה ב-Vercel

1. העלו את תוכן הריפו ל-GitHub (ר' סעיף "פריסה" למטה לגבי קובץ ה-ZIP).
2. בפרויקט Vercel חדש, חברו את ה-repo.
3. Vercel יזהה אוטומטית את `vercel.json` ואת `api/index.py` כ-Python
   Serverless Function.
4. הגדירו את משתני הסביבה (ר' הסעיף הבא) תחת Project Settings -> Environment Variables.
5. בצעו Deploy. כתובת ה-API שלכם תהיה:
   ```
   https://<your-project-name>.vercel.app/api/index
   ```

**הערה על pydub/ffmpeg:** `transcription.py` עובד רק מול קבצי `.wav`
(בדיוק כפי שסופק בקוד המקורי - `AudioSegment.from_wav`), ולכן אינו
תלוי בהתקנת `ffmpeg` בשרת ה-Vercel. אם בעתיד יורחב תמיכה לפורמטים
נוספים (למשל ogg), ייתכן שיידרש layer/תוספת עם ffmpeg - מחוץ לתחום
הפרויקט הנוכחי.

## משתני סביבה

יש להגדיר את המשתנים הבאים ב-Vercel (Project Settings -> Environment Variables):

| משתנה | תיאור | חובה |
|---|---|---|
| `HF_S3_NAMESPACE` | שם המשתמש/הארגון שלכם ב-Hugging Face | כן |
| `HF_S3_ACCESS_KEY` | מפתח S3 (מתחיל ב-`HFAK...`) | כן |
| `HF_S3_SECRET_KEY` | הסוד המשויך למפתח | כן |
| `HF_S3_BUCKET` | שם ה-bucket שיצרתם | כן |
| `YEMOT_RECORDING_DIR` | תיקיית השמירה הזמנית של הקלטות ב-ivr2 (ברירת מחדל: `/5`) | לא |

**שימו לב:** אין (ובכוונה) משתני סביבה עבור מספר המערכת/סיסמת הניהול
של ימות המשיח. טוקן ה-API של ימות (להורדת קובצי ההקלטה דרך
`DownloadFile`) **אינו** נשמר ב-Vercel כלל - הוא מוגדר פעם אחת
בהגדרות השלוחה עצמה (`ext.ini`, ר' הסעיף הבא) ומגיע לשרת שלנו בכל
בקשה כפרמטר. מומלץ להנפיק טוקן API קבוע (שאינו פג תוקף) דרך אתר
הניהול של ימות המשיח, ולא להשתמש בפורמט הישן `מספר_מערכת:סיסמה`.

## הגדרת השלוחה בימות המשיח

ראו את `ext.ini.example` לדוגמה מלאה ומוערת. בתמצית:

1. צרו שלוחה חדשה (לדוגמה שלוחה `5` תחת השלוחה הראשית).
2. הגדירו בקובץ `ext.ini` שלה:
   ```ini
   type=api
   api_link=https://YOUR-PROJECT-NAME.vercel.app/api/index
   api_url_post=yes
   api_dir=/5
   api_add_0=ApiYemotToken=YOUR-YEMOT-API-TOKEN
   api_000=Utterance,,record,/5,recording,no,yes,3,25
   ```
   כאשר `YOUR-YEMOT-API-TOKEN` הוא טוקן API קבוע שהונפק דרך אתר הניהול
   של ימות המשיח (ר' "משתני סביבה" לעיל) - `api_add_0` הוא המנגנון
   התיעודי של ימות לצירוף פרמטר קבוע לכל פנייה לשרת ה-API.
3. העלו קובץ שמע/TTS בשם `000` לשלוחה - זו הודעת הפתיחה שתישמע
   למתקשר לפני ההקלטה הראשונה (למשל: "אנא אמרו למי להתקשר").
4. (אופציונלי) הגדירו `api_record_beep=no` אם אינכם רוצים צליל "ביפ"
   לפני תחילת ההקלטה.

**חשוב:** כל שאלת הקלטה במודול (גם זו שבקובץ `ext.ini` וגם אלו
שמוחזרות דינמית מהשרת דרך `read`) מוגדרת מסוג **`record`** בלבד - לא
`voice`. כך ימות שומרת רק את ההקלטה הגולמית, ואינה מפעילה את מנוע
התמלול המובנה שלה. כל התמלול מתבצע אך ורק בקוד שלנו
(`transcription.py`), בהתאם לדרישה המפורשת.

## זרימת השיחה

### 1. חיוג ישיר (ברירת מחדל)

המתקשר שומע הודעת פתיחה ומתבקש לדבר. ה-API מתמלל את מה שנאמר ובודק:

- **מספר טלפון** (כולל ספרות שנאמרו במילים, כמו "אפס חמש שתיים...") -
  ניתוב ישיר (`routing=...`) ושמירה בהיסטוריה.
- **שם איש קשר קיים** (התאמה מדויקת או מקורבת) - איתור ב-JSON וניתוב.
- **"שיחות אחרונות"** - מעבר לתפריט שיחות אחרונות.
- **"אנשי קשר"** - מעבר לתפריט אנשי קשר.
- **"הוסף איש קשר"** - מעבר לזרימת הוספת איש קשר.
- אחרת - הודעת שגיאה ("לא הבנתי את הבקשה...") וסיום.

### 2. תפריט "שיחות אחרונות"

המערכת מקריאה את היעדים האחרונים ("לשיחה ל-X אמרו 1..."), מקליטה את
תשובת המתקשר (מספר), מתמללת, ומחייגת ליעד הנבחר.

### 3. תפריט "אנשי קשר"

המערכת מקריאה את רשימת השמות, מקליטה את תשובת המתקשר (שם), מתמללת,
מאתרת ומחייגת.

### 4. "הוסף איש קשר"

דו-שיח דו-שלבי (מנוהל באמצעות `read` - ר' הסבר למטה):
1. הקלטת שם איש הקשר.
2. הקלטת מספר הטלפון (מילים או ספרות).
3. שמירה ב-JSON והשמעת אישור.

### כיצד נשמר "מצב" השיחה בלי session?

ה-API הוא **stateless** לחלוטין מצד הקוד שלנו. כל "זיכרון" של היכן
נמצאים בדו-שיח מגיע מתוך **הפרמטרים שימות שולחת בכל בקשה** - בזכות
מנגנון ה-`read` של מודול ה-API: כאשר השרת עונה בפעולה מסוג `read`,
ימות מוסיפה לבקשה הבאה את כל מה שנאסף עד כה (כולל הפרמטר החדש).
כך, למשל, בזרימת "הוסף איש קשר" - אם הפרמטר `NewContactPhone` כבר
קיים בבקשה שהתקבלה, ה-API יודע שזהו הסיבוב השלישי (יש כבר שם וטלפון)
ושיש לשמור ולסיים.

## בדיקות ופתרון תקלות

### בדיקה מקומית (ללא חיוג אמיתי)

ניתן לבדוק את לוגיקת הניתוב וה-storage באופן מבודד (ללא תלות ברשת):

```bash
cd api
python3 -c "
import storage
data = storage._empty_user('0501234567')
data = storage.add_contact(data, 'בעלי', '0521111111')
print(storage.find_contact(data, 'בעלי'))
"
```

### לוגים בימות

ימות שומרת לוג של כל הפניות/תשובות בקובץ `LogApi.ymgr` תחת תיקיית
`Log` בשלוחה הראשית - שימושי לאבחון תקלות תקשורת מול ה-API.

### תקלות נפוצות

| תסמין | סיבה אפשרית |
|---|---|
| "אין מענה משרת API" (`M1607`) | כתובת `api_link` שגויה, או שה-endpoint מחזיר שגיאה/timeout |
| שגיאה על משתני סביבה חסרים | לא הוגדרו `HF_S3_*` ב-Vercel |
| שגיאה "חסר טוקן ימות בבקשה" | `api_add_0=ApiYemotToken=...` לא הוגדר (או הוגדר עם שגיאת הקלדה) ב-`ext.ini` של השלוחה |
| תמלול ריק תמיד | בדקו שההקלטה נשמרת כ-wav תקין בנתיב `YEMOT_RECORDING_DIR`, ושהטוקן שהוגדר ב-`api_add_0` (`ApiYemotToken`) ב-`ext.ini` תקין ולא פג תוקף |
| "לא מצאתי איש קשר" על שם קיים | ייתכן אי-דיוק בתמלול - נסו שם קצר/ברור יותר, או בדקו את כתיב השם ב-JSON |

## מגבלות ידועות

- **שיטת התמלול** (`recognize_google` ללא API key) משתמשת במפתח
  פנימי לא-רשמי של ספריית SpeechRecognition. אין ערבות זמינות/יציבות
  רשמית מצד גוגל - מתאים לשימוש אישי/משפחתי, לא לשירות production
  בקנה מידה גדול (כפי שצוין גם בקוד המקורי שסופק).
- **זיהוי ספרות שנאמרות במילים** תומך באוצר מילים בסיסי בעברית
  (אפס-תשע). ביטויים לא סטנדרטיים (למשל "אחת עשרה" כמילה אחת) לא
  יזוהו נכון כרגע - ניתן להרחיב את המילון ב-`api/index.py`
  (`HEBREW_DIGIT_WORDS`).
- **התאמת שמות אנשי קשר** מבוססת על התאמה מדויקת/מקורבת (containment)
  פשוטה - לא אלגוריתם "fuzzy matching" מתקדם. שמות דומים מאוד עלולים
  להתבלבל.
- כל שיחה פותחת הקלטה **חדשה** (אין "זיהוי לקוח קבוע" מעבר למספר
  המתקשר `ApiPhone`) - כלומר אם שני אנשים משתמשים באותו מכשיר/קו,
  הם חולקים את אותו קובץ אנשי קשר/היסטוריה.
